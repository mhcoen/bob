The proposal is not ready for acceptance. The prior round's confirmed defects are closed, and I checked each against the current text. Four new or reopened problems block, and several smaller ones should be fixed in the same pass.

## What the revision resolved

The staging-model lease in D-033 now covers smoke tests before an installation row exists. D-022 publishes blobs with a claim, a verify-and-reference path and a no-replace rename. D-003 registers job scratch inside the service container with a creator lease. D-004 orders interactive work by capture sequence and reserves preview separately, and D-027 charges decode, materialization and diarization explicitly with arithmetic that checks out. D-010 introduces a single DeliveryExecutor. D-006 and I8 add a non-terminal interrupted_resumable state that D-031 and D-043 use consistently. D-023 and D-037 make cross-window identity a proposal with stated thresholds and remove the unreachable assigned state. The import bookmark is gone, orphan notice directories are swept, the usability sample is defined, and the Text delivery coverage no longer claims automatic clipboard placement. D-025 now withholds automatic resume from every real player, which matches REVIEW_NOTES rather than the prior judge's waiver and is the honest outcome.

## Blocking

**1. Confirmed delivery has no defined evidence source, so modifier submission is unreachable.** D-009 says confirmed requires supported operation acknowledgment from a target adapter. The TextInserter port exposes acknowledgment only where supported semantics exist. F4 says successful trials cannot create an acknowledgment guarantee, and the open question repeats that. No decision states what evidence would qualify. The concrete case is a synchronous success return from setting the selected-text attribute. That call returns after the target's accessibility server has processed the set, which is the target acknowledging the operation. RESEARCH only says that failure codes carry no guarantee. If success plus a per-target F4 check counts, TextEdit, Mail, Notes and Xcode get confirmed delivery and the specification's modifier submission exists. If it does not count, every attempt in the product ends unconfirmed, no target can ever qualify because Apple documents no paste acknowledgment for any application, and the requirement has no design path. The Text delivery coverage entry claims submission semantics are covered without saying which. Resolve by deciding this in D-009, recording the reason, and stating the consequence for submission in coverage.

**2. The paste barrier in D-010 makes the common delivery path a one-click-per-dictation workflow, and the cheaper alternative was not weighed.** For any target without accessibility insertion, which includes Chrome, VS Code, Slack, Terminal and Figma in the F4 list, each paste creates a barrier that blocks all later automatic delivery and holds the user's clipboard until a manual resolution. The previous judge asked for executor serialization, which the design now has. The barrier is a further step whose cost is deferred to a non-blocking open question. The D-010 alternatives omit the option the executor makes possible: sequencing paste attempts under one snapshot chain, with the residual risk that a still-undelivered Command-V from attempt one consumes transcript two. That residual is the same class the design already accepts for accessibility writes, where later independent attempts are permitted. They also omit treating the next capture trigger as the user action that retires a barrier, with the panel showing the pending state. Choose among these with the residual stated, and give F4 a review-actions-per-dictation acceptance figure with a return-to-owner action rather than a measurement with no consequence.

**3. D-017 does not say which runtime performs translation.** Translation is a separate derived operation after source recognition, and descriptors carry translation language claims. Nothing says whether the operation is Whisper's translate task over audio or the generation model over the transcript. The two differ in model kind, admission charge under D-027, stage in D-006's state list, evaluation in F1, and what compatibility per model means for a user-supplied model. The specification asks for compatibility per model, which cannot be described until the model kind is named. Decide it and record the alternative.

**4. The capture backlog rule contradicts the ring and the loss bound.** D-006 stops input after four seconds without writable ownership because the ring holds five seconds. D-004 then defines writer backlog thresholds of thirty and sixty seconds. A backlog that large can only exist as frames the writer removed from the ring but has not made durable, which is unflushed memory that D-030's chunk pipeline never mentions and the 128 MiB capture charge does not name. F3's four-second loss bound is stated for tested storage conditions, but the design never says that a crash during a stall loses up to the backlog cap. Define what the backlog is, where it lives, its memory charge, and the crash-loss bound under a stall. The "durable prefix" retained at sixty seconds needs the same definition.

## Improvements that can wait

**Capture format in D-030 reverses an accepted decision without a basis.** The prior round accepted live ALAC with full packet-table accounting. This revision stores raw Float32 PCM at 48 kHz and dismisses ALAC for the recovery problem the prior round already solved. No reason is given for Float32 or for 48 kHz on the microphone stream. The storage consequence for the most common operation is large.

| Path | Prior design | This design |
|---|---|---|
| Dictation, per hour | about 55 MB | about 691 MB |
| Meeting, per hour | native-rate ALAC | about 2.07 GB |

Default retention is manual. Either record the basis for Float32, or capture Int16 or Int24 and make post-seal lossless compression part of the design with its publication rule, and add a size warning or default retention for meetings.

**The durability target is undefined.** D-030 synchronizes files, directories and the journal three times per chunk, but never says whether that is fsync or full flush. On macOS, fsync does not flush the drive cache. F3 kills the writer process, which tests app-crash durability that needs no synchronization at all. State whether the loss bound covers app crash, kernel panic or power loss, and choose the call accordingly.

**Materialization copies the speech model three times.** D-040 keys by service kind, and D-011 lets preview use the primary model. That model then exists in the blob store and in two service containers. The D-003 alternative dismisses a read-only path exception as broader persistent access, which overstates a read-only grant scoped to the blob directory. A shared group container available to all sandboxed services is a documented mechanism that is not weighed at all.

**Echo has no stated consequence.** D-023 performs no echo handling. On a Mac without headphones, remote speech reaches both streams, so it is recognized twice and appears twice in the transcript and in notes. State that consequence, and weigh the system voice-processing option on the microphone path, which the design does not mention.

**The memory equivalence protocol may be unresolvable by construction.** The margin is fixed at 1 MiB per processed hour, resolvability is declared unknown, and inconclusive blocks acceptance of the adapter indefinitely. Resolvability depends on checkpoint sampling density, which the protocol does not specify. Specify it, and prespecify a rule that sets the margin from pilot variance rather than leaving a fixed figure that no later evidence may change.

**Whole-input diarization lost its reconsideration path.** The prior revision windowed only where F5 showed growth. D-023 now windows unconditionally, dismisses whole-input analysis for the memory question F5 exists to answer, and lists only a new incremental diarizer as the trigger to revisit. Add a flat F5 result as a reconsideration condition, since windowing is what creates the per-window confirmation burden.

**Smaller gaps.** D-012 now auto-delivers generated text when checks are unavailable, reversing the accepted prior disposition without a recorded reason and with no per-mode option. Neither D-004 nor D-011 states whether preview and final models stay resident while idle, which sets the idle footprint and cold-start latency F1 measures. The serialized RunManifest has a hash in processing_runs but no stated storage location. D-020 cites WhisperKit documentation for a whole-file versus incremental loading distinction that appears nowhere in the supplied RESEARCH text.

Resolving the four blocking items needs no measurement. Each is a decision the design can make from the material at hand, with the alternative and residual recorded. No project files were changed.
